Sparse-View 3D Reconstruction: Zero123++ & 3D Gaussian Splatting
This project integrates Zero123++ (consistent multi-view generation from a single image) with 3D Gaussian Splatting (3DGS) (real-time high-quality 3D rendering) to achieve fast sparse-view 3D modeling and reconstruction from a single input image.

1. Environment Setup
IMPORTANT NOTE FOR TEAM MEMBERS:
Because 3DGS relies on custom C++/CUDA compiled plugins that are heavily tied to specific hardware (GPU architecture), DO NOT directly copy someone else's virtual environment folder. Please strictly follow the steps below to build the environment on your own machine.

System Requirements
OS: Linux (or Windows WSL2 environment)

Hardware: NVIDIA GPU (Compute Capability 7.0 or higher)

Dependencies: CUDA Toolkit (ensure nvcc --version works) and basic build tools (g++).

Step 1: Create a Conda Virtual Environment
Please use Python 3.11 to ensure package compatibility:

conda create -n sparse_3d python=3.11 -y
conda activate sparse_3d

Step 2: Install Core PyTorch
Install PyTorch 2.11 compatible with CUDA 12.8:

pip install torch==2.11.0+cu128 torchvision==0.26.0+cu128 torchaudio==2.11.0+cu128 --extra-index-url https://download.pytorch.org/whl/cu128

Step 3: Install Unified Dependencies
Install the requirements provided in the root directory:

pip install -r requirements.txt

Step 4: Compile Custom 3DGS CUDA Plugins (CRITICAL)
Navigate to the gaussian-splatting directory. If you are using WSL, first clean up any leftover Windows identifier files that might interfere with the compilation, then proceed with the standard installation:

cd gaussian-splatting

Clean up Zone.Identifier junk files in WSL (Native Linux users can skip this):
find . -name "Zone.Identifier" -type f -delete

Recompile and install the three submodules sequentially (DO NOT use -e mode):
cd submodules/diff-gaussian-rasterization
pip install . --no-build-isolation --no-cache-dir

cd ../fused-ssim
pip install . --no-build-isolation --no-cache-dir

cd ../simple-knn
pip install . --no-build-isolation --no-cache-dir

cd ../..

2. Zero123++ Usage Guide
Zero123++ takes a single input image and generates multi-view images at fixed camera poses (Azimuth: 30, 90, 150, 210, 270, 330 / Elevation: 20, -10).

Running the Test Script
You can use the following example script to convert a single image into multi-view images:

cd zero123plus
python examples/img_to_mv.py

(Note: The first time you run this, it will automatically download model weights from Hugging Face. If you encounter a security warning during loading, ensure the DiffusionPipeline in your code includes the trust_remote_code=True parameter.)

Launching the Interactive UI
You can also launch a graphical interface to test the generation interactively:

Streamlit UI:
streamlit run app.py

Gradio UI:
python gradio_app.py

3. 3D Gaussian Splatting (3DGS) Usage Guide
3DGS optimizes the multi-view images and camera parameters (SfM format) prepared in the previous step to train a real-time renderable 3D model.

Data Preparation
Ensure your dataset is converted to the COLMAP format or follows the NeRF Synthetic folder structure. For images generated by Zero123++, remember to crop the multi-view grid image into individual frames and compute the corresponding transforms.json or cameras.bin based on the fixed camera poses.

Start Training
Run the following command to start optimizing the 3D Gaussian model:

cd gaussian-splatting
python train.py -s <path_to_your_dataset> -m <model_output_path>

Common Parameters:
-s or --source_path: Directory path of the input dataset.
-m or --model_path: Location to save the trained model (defaults to output/<random_string>).
-w or --white_background: Add this flag if your input images have transparent/removed backgrounds and you want to train with a white background (default is black).
--iterations: Set the number of training iterations (default is 30,000).

Render & Evaluate
After training, use the following command to render the trained model into images or a video:

python render.py -m <model_output_path> -s <path_to_your_dataset>

If you used the --eval flag during training to split a test set, you can then calculate quantitative metrics like PSNR:

python metrics.py -m <model_output_path>
